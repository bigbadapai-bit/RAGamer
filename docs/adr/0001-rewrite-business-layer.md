# 业务层全部重写，不复用原项目代码

新项目以既有的中文产品手册 RAG 项目（掌柜智库）为参照，但**只借鉴其设计经验，不搬运其代码**。

审计后原项目只有约 900 行（16%）可零改动复用，而业务层 3860 行 Python 加 1253 行前端（73%）本就需要重写；那 900 行还会连带继承死代码、缺失 25 个键的 `.env.example`、零测试与零 lint。为省 900 行的重写而继承一整套债务不划算，何况新项目要加多路召回、双正交标签与版本过滤，沿用旧的状态结构只会变成"先搬过来再改"。

**代价**：原项目排查过的坑会重新踩一遍。所以那些坑必须被整理成一份显式的「必须继承」清单随新项目走，而不能指望代码本身携带它们——这是本次重写最容易失守的地方。
