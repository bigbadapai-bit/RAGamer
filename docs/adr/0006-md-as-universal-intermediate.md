# 一切输入先归一为 Markdown

PDF、图片、网页链接都先转成 Markdown，之后所有环节（图片处理、切分、打标、向量化、入库）**只面对 md 一种形态**。

管线由此只有一个归一化点。若不这样做，每种来源都要在两个地方各写一套分支：图片处理里判断"这份内容来自哪里"，切分里再判断一次——改动一处就要动多处。归一之后，新增一种来源只影响它自己那一个环节。

**降级阶梯没有消失，只是内移了。** 原来的思路是按文件格式分档（结构化／半结构化／扁平／图片），现在变成"**这条 md 有没有可用的标题结构**"。判定更简单（只看标题密度），而且同一条 md 内部可以两种切法并存——一份自制文档可能前半有标题、后半是粘过来的大段文字。

**代价有两处**：其一，独立上传的攻略截图要绕一圈转成 md 再回头取图里的文字，看起来比直接 OCR 多此一举；其二，把解析质量的责任集中押在了 MinerU 一个环节上。第一处是这层间接的固有成本，第二处由导入链路的产物校验来兜底。
