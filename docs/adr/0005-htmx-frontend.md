# 前端用 htmx，不用 React

界面用 FastAPI + Jinja2 + htmx + Tailwind，而不是沿用参照对象 RAGFlow 的 React 单页应用。

RAGFlow 的前端实测为 1730 个文件、约 20 万行业务代码（多人团队数月至一年的量），不具备参照价值。本项目界面只需五个页面，且开发者**没有前端经验、只熟悉 FastAPI**，代码将由 AI 生成——这意味着真正的风险不是"能否写出来"，而是"**出错时能否定位**"：htmx 是 HTML 属性，出错时看到的是一行可读标记；React 出错时是 hook 依赖与状态提升，没有前端经验便无从下手。

另有一个正面理由：澄清反问是典型的服务端驱动交互（后端判断需要澄清 → 返回带候选的片段 → 用户选择 → 回传恢复），这恰好是 htmx 的强项；用 React 反而要在客户端额外维护一套挂起与恢复的状态机。

**代价**：界面精致度不如成熟组件库；流式逐字输出在 htmx 中较别扭，对话页那一小块允许退回原生 `EventSource`。**这是一条基于团队约束而非技术优劣的决定**——将来若具备前端能力，重写为 React 不需要重新论证架构。
